# UI/UX Acceptance Checklist

This checklist covers the frontend-only workspace delivered on `feature/eitaa-miniapp-uiux-2026-11-11`.

## Browser preview (no Gateway required after the UI is opened)

- [ ] Confirm the login panel fits a 320px-wide viewport without horizontal scrolling.
- [ ] Confirm Persian digits and Latin digits can be entered in the mobile field.
- [ ] Confirm OTP panel, back navigation, disabled/loading button states, and status messages.
- [ ] After successful authentication with a test Gateway, confirm the dashboard renders.
- [ ] Navigate between Home, Chat, Tickets, Knowledge, and Profile.
- [ ] Confirm desktop sidebar and mobile bottom navigation indicate the active page.
- [ ] Confirm chat composer validates empty input and retains messages during page navigation.
- [ ] Confirm chat UI explicitly states that messages are not sent until the Gateway integration exists.
- [ ] Fill ticket title and description; confirm local preparation feedback and no false "ticket created" success.
- [ ] Search the sample knowledge cards; confirm empty search state.
- [ ] Confirm Profile displays only identity fields actually returned by the authenticated session.
- [ ] Confirm logout returns to login and does not expose the access token.
- [ ] Check keyboard focus visibility and reduced-motion preference.
- [ ] Check 320px, 360px, 390px, 768px, and desktop viewport widths.

## Eitaa WebView / server validation (requires deployment)

- [ ] Load the app in the official Eitaa WebView and verify SDK lifecycle behavior.
- [ ] Verify the deployed origin, TLS, CSP, font loading, and official Eitaa SDK loading.
- [ ] Verify Gateway CORS allow-list for the exact deployed origin.
- [ ] Verify OTP request/verify against the current Gateway OpenAPI contract.
- [ ] Verify session expiry, unauthorized responses, network timeout, retry, and rate limiting.
- [ ] Verify all real Chat, Ticket, and Knowledge routes against documented Gateway contracts before enabling network calls.

## Important scope

Chat and ticket forms are UI scaffolding only. Chat replies are not generated by an LLM, ticket drafts are not submitted, and knowledge cards are sample placeholders. No backend route or payload is inferred by this UI work.

No browser automation, Eitaa WebView, Gateway, or server tests are claimed as executed by this change.
